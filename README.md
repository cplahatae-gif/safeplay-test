# SAFEPLAY 테스트판

컨베이어 현장 한 곳에서 재가동 전 판단을 연습하는 브라우저 게임입니다. 약 1~2분짜리 시나리오 하나를 구현했습니다.

## 실행

```sh
npm ci
npm run dev
```

브라우저에서 http://127.0.0.1:5173/ 를 엽니다. 이미 개발 서버가 실행 중이면 설치와 실행을 반복하지 않습니다.

- A/D 또는 방향키: 통로 이동
- E: 가까운 설비나 동료 조사
- Esc: 조사와 선택 화면 닫기
- 숫자 1/2/3 또는 마우스: 대응 선택

화살표를 누르고 있으면 연속 이동합니다. 한글 입력 상태에서도 이동과 E 조사가 동작합니다.

## 시연 흐름

현장 진입 → 오른쪽으로 이동 → 제어반과 동료 각각 조사 → 대응 결정 → 1번 오답 → 놓친 단서 확인 → 동료 재조사 → 3번 선택 → 동료와 확인하는 현장 변화 → 최종 질문의 2번 선택 → 최초 판단과 최종 판단 확인.

## 구현 범위

2D 기반 2.5D: 고정 시점 배경, 투명 작업자 이미지와 전경 난간을 합성합니다. 작업자는 통로의 원근에 맞는 바닥선을 따라 움직이고, 접지 그림자와 난간 가림을 적용합니다. 걷기는 네 프레임으로 표현합니다.

Phaser(브라우저 게임 엔진), Vite(개발 서버와 빌드 도구), TypeScript(타입을 검사하는 자바스크립트)를 사용했습니다. 결과물 만들기는 `npm run build`, 고정 판정과 재시도 검사에는 `npm test`를 사용합니다.

## 확인 범위와 한계

`npm run build` 통과, 고정 판정 검사 `npm test` 1건 통과. 마지막 코드 변경을 반영한 Chrome 통합 플레이에서 오답, 재시도와 최종 완료를 확인했습니다.

- 실제 Chrome에서 대표 화면, 방향키 이동, E 조사, 숫자와 마우스 선택, 오답 후 재시도, 동료 상태 변화와 최종 결과를 확인했습니다.
- 모든 상황과 정답은 가상 데모 규칙입니다. 현장 위험성평가표와 담당자 검토는 아직 연결하지 않았습니다.
- 피드백은 사전 작성 문구입니다. OpenAI API와 비밀 키를 사용하지 않습니다. 화면에도 AI 미연동으로 표시합니다.
- 배경과 조명은 정지 이미지이며, 동적 조명이나 실제 3D 설비를 구현하지 않았습니다. 기본 대상은 키보드가 있는 데스크톱 브라우저입니다.
- 현재 걷기는 비슷한 자세의 이미지 네 장을 반복하므로 발걸음과 이동이 자연스럽게 이어지지 않습니다. 연속 동작 자산과 동료 애니메이션으로 개선하는 방향을 검토했으며, 아직 적용하지 않았습니다.

## 자산과 제작 경로

OpenAI game-studio의 Phaser, 스프라이트 제작, 플레이 검증 스킬 문서를 참고했습니다. 시각 자산은 Codex의 기본 이미지 생성 도구로 만들었습니다. 별도 플러그인 설치는 하지 않았습니다.

`public/assets/`의 PNG 네 개는 같은 횡스크롤 참고 화면을 바탕으로 생성했습니다. 읽어야 하는 한국어와 조작 안내는 게임 코드가 표시합니다.

| 파일 | 생성 방식과 요청 요약 | 크기 |
|---|---|---|
| background.png | 참고 이미지 편집. 사람과 화면 정보를 제거하고 컨베이어, 모터, 방호망, 통로, 따뜻한 작업등과 차가운 외부광을 유지 | 1672×941 |
| worker.png | 오른쪽을 향한 실제적인 작업자 걷기 네 프레임. 흰 안전모, 고시인성 조끼, 남색 작업복, 동일 조명, 투명 배경 | 2117×743 |
| coworker.png | 설비 가까이에서 공구를 사용하는 웅크린 작업자와 공구함. 같은 복장과 조명, 투명 배경 | 1476×1066 |
| railing.png | 참고 구도의 가까운 노란 난간만 추출. 원래 화면 좌표와 크기를 유지하고 나머지는 투명하게 처리 | 1672×941 |

asset-info.json은 투명 작업자 이미지의 발 위치를 기록합니다. src/main.ts는 배경과 전경 가림, 이동, 조사 화면을 연결하며 src/rules.ts는 고정 판정과 재시도 상태를 관리합니다.
